# AI 多人情感有声书 · 设计文档

- 日期：2026-09-24
- 状态：待评审
- 范围：v1（不含视频模块）
- 定位：**个人本地使用**的小说转多人情感有声书自动化流水线，不做账号、多租户、计费

---

## 1. 背景与目标

### 1.1 来源

本设计是对现有 `datavrapCast`（`D:\workspace\datavrapCastV1.1.0`）的功能复核与重写。现有系统为 Spring Boot 单体 + 本地 OmniVoice TTS 服务，功能上已经跑通"txt → 分章 → AI 角色分析 → 逐行克隆合成 → 章节 wav+srt"，但排查中发现以下结构性问题：

| 问题 | 证据 |
|---|---|
| 生成任务无守护、无幂等 | 前端按钮不禁用，`generateAudio` 无运行中判断；实测进度在 648↔755 之间来回跳，确认两条并行流水线重复合成 |
| 状态以数组位置为 ID，JSON 非原子写 | 行号即数组下标，片段名 `audio/{章}_{行:003}.wav`；插入/删除一行会整体平移，行数不变时会复用错位音频 |
| 生成参数不进缓存键 | `line_status_N.json` 只判断位置 + `done`，改音色/参数后旧片段仍被复用 |
| TTS 引擎硬耦合 | 调用链写死 OmniVoice 字段（`text/ref_audio/ref_text/num_step/speed`），且该引擎**没有情感输入** |
| 字幕时间轴靠字数比例估算 | `generateSrt` 用 20 字硬切 + 按字符数分摊时长；行间停顿完全未建模 |
| 长文本分析无场景概念 | 按 3000 字符硬切块独立送模型，块间无共享上下文，说话人/语气漂移 |
| 采样率混排会静默损坏 | 实测 24kHz+22.05kHz 各 1 秒拼接 → 输出 1.9187 秒，第二段被当作 24kHz 播放，变速变调且不报错 |
| 文本未清洗 | 《地球最后一个修仙者》原文含站点水印与广告行，现有分析将其保留为"旁白" |

### 1.2 目标

1. **零人工主流程**：导入 → 分析 → 生成，全程可无人值守跑完整本。
2. **多人 + 情感**：四层情感模型（角色底色 → 关系 → 场景 → 句级），支持"对谁说什么话"的差异化演绎。
3. **可中断、可续跑、可局部重算**：断点粒度到"行"，改一句只重算一句。
4. **引擎可替换**：v1 主引擎 IndexTTS-2.5，接口层不绑定具体引擎。
5. **产物可直接消费**：章节与整本的 wav/srt/mkv，手机播放器/音频软件开箱可用。

### 1.3 非目标（v1 明确不做）

- 账号体系、多用户、计费、公网 SaaS
- 跨机器分布式 worker 调度
- 视频/配图模块（M5，独立 spec）
- 移动端原生 App（用浏览器访问即可）

## 2. 总体架构

### 2.1 三个可独立启动的角色（同一代码库，不同子命令）

| 角色 | 职责 | 说明 |
|---|---|---|
| `serve` | HTTP API + 静态前端托管 + SSE 进度推送 | 只处理快请求：入队、查询、读文件、试听代理；**永不执行长任务** |
| `worker` | 角色分析、合成、后期、导出 | 长驻进程，可多开；崩溃后由租约机制自动回收重跑 |
| `tts` | 引擎推理服务（IndexTTS-2.5 封装为 HTTP 服务） | **独立部署、独立启停、可放另一台机器**，与后端解耦 |

长任务必须进 worker：分析角色文本、生成有声书这类任务的耗时是分钟到小时级，接口只负责"入队 + 返回 jobId"。

### 2.2 技术选型

| 部分 | 选择 | 理由 |
|---|---|---|
| 后端 | Python 3.13 + FastAPI（uv 管理解释器与依赖） | 与 TTS 生态同语言；异步 IO 适合调度；uv 提供可复现的锁定环境 |
| TTS 服务 | Python 3.10–3.11（IndexTTS-2.5 的硬性要求）+ FastAPI | 独立项目、独立虚拟环境，与后端版本解耦；升级后端不受其限制 |
| 队列/状态 | SQLite（WAL） | 单机、任务量级为每日数百，原子领取 + 租约足够；**不引入 Redis/Celery** |
| 内容存储 | 本机文件（JSON/JSONL + WAV） | 可直接查看、备份、diff、手工修正；符合"分析结果落文件"的要求 |
| 前端 | React + Vite + CSS 变量（由 `serve` 托管） | 单页应用，手机浏览器同款 |
| 音视频处理 | ffmpeg（外部进程） | 拼接、重采样、响度、字幕封装 |

### 2.3 数据流总览

```
txt ──► 分章 ──► PassA 角色与关系 ──► PassB 场景切分 ──► PassC 逐句标注
                                                              │
                                        ┌─────────────────────┘
                                        ▼
                          voices/casting.json（角色-音色映射）
                                        │
                                        ▼
                    逐行合成（worker → tts 服务，按行并行 + 缓存命中跳过）
                                        │
                                        ▼
                   韵律与后期（插停顿、响度、统一采样率、章节拼接）
                                        │
                                        ▼
               产物：chapter_N.wav/.srt/.mkv，book.wav/.srt/.mkv，issues.jsonl
```

## 3. 任务系统

### 3.1 队列表（SQLite）

```sql
CREATE TABLE jobs (
  id              INTEGER PRIMARY KEY,
  kind            TEXT NOT NULL,          -- chapter_split|characters|scenes|lines|synthesize|post|export|migrate
  book_id         TEXT NOT NULL,
  chapter_index   INTEGER,                -- 章粒度任务使用；书粒度任务为 NULL
  status          TEXT NOT NULL,          -- queued|running|done|failed|canceled
  priority        INTEGER NOT NULL DEFAULT 100,
  attempts        INTEGER NOT NULL DEFAULT 0,
  max_attempts    INTEGER NOT NULL DEFAULT 3,
  not_before      INTEGER,                -- 退避：毫秒时间戳
  lease_expires_at INTEGER,
  worker_id       TEXT,
  progress        TEXT,                   -- JSON：{done,total,current,message}
  error           TEXT,
  created_at      INTEGER NOT NULL,
  updated_at      INTEGER NOT NULL
);
CREATE UNIQUE INDEX uq_jobs_active ON jobs(kind, book_id, IFNULL(chapter_index,-1))
  WHERE status IN ('queued','running');
```

**原子领取**（WAL 模式 + `BEGIN IMMEDIATE`）：

```sql
UPDATE jobs
   SET status='running', worker_id=?1, lease_expires_at=?2, attempts=attempts+1, updated_at=?2
 WHERE id = (SELECT id FROM jobs
              WHERE status='queued' AND (not_before IS NULL OR not_before<=?2)
              ORDER BY priority, id LIMIT 1)
   AND status='queued';
```

worker 每 10 秒续租（`lease_expires_at = now + 30s`）。租约过期视为 worker 死亡，任务回到 `queued` 被其他 worker 重领 —— 进程被 kill、断电、蓝屏都不需要人工清理。

唯一索引保证：重复提交同一章同一类型的任务只会命中同一条记录，**从根上消除"点两次生成跑两条流水线"**。

### 3.2 任务依赖（DAG，不引入工作流引擎）

用"前置完成后入队"表达依赖：

```
chapter_split(书) → characters(书)
characters(书)    → scenes(章) × N
scenes(章)        → lines(章)
lines(章)         → casting(书)
casting(书)+lines(章) → synthesize(章)
synthesize(全部章) → post(章) → export(书)
```

### 3.3 并发策略

| 资源 | 策略 |
|---|---|
| LLM | 按"配额无限"处理，**不做 RPM/TPM 令牌桶**；只保留可配置并发上限（默认 8，可调 4–16）。连续 429/超时自动降一档并退避 60 秒，稳定后逐级恢复 |
| TTS | 客户端不拍数字：worker 汇总各 TTS 实例 `/health` 自报的可用并发作为投递上限 |
| 显存保护 | 出现 OOM/连续 5xx 时全局降一档 + 熔断 60 秒；恢复后逐步回升 |

### 3.4 取消、暂停、重试

- **取消**：每处理一行前检查 cancel 标志，秒级生效；已完成的产物保留。
- **暂停**：全局 / 单书两级，恢复即从断点续跑。
- **可自动重试**：网络超时、429、TTS 5xx、显存不足、文件占用 —— 指数退避 + 抖动，最多 3 次。
- **毒丸保护**：同一行失败 3 次即停，写入 `issues.jsonl` 并**跳过继续**，绝不阻塞整本流程。
- **失败可见**：降级/失败一律进异常清单，不允许静默把对白读成旁白。

## 4. 数据模型与文件布局

### 4.1 目录结构（文件是事实来源，数据库只存索引与队列）

```
data/
  service.db                          SQLite：任务队列、索引、调用统计
  books/<bookId>/
    book.json                         元信息：书名、来源、章节数、状态、创建时间
    chapters.json                     分章结果（index/title/字符数/清洗统计）
    source/original.txt               原始上传文本（只读留档）
    analysis/
      characters.json                 角色档案 + 别名 + 关系矩阵（全书级）
      scenes/chapter_0001.json        场景切分 + 参与者 + 基调 + 摘要
      lines/chapter_0001.jsonl        逐句标注（一行一句）
    voices/casting.json               角色-音色映射与参数
    audio/chapter_0001/
      000123.wav                      文件名 = 稳定行 ID（非数组位置）
      000123.meta.json                内容哈希、引擎、版本、参数、时长
    output/
      chapter_0001.wav / .srt / .mkv
      book.wav / .srt / .mkv
    issues.jsonl                      异常清单（降级、重试失败、待人工确认）
    logs/                             worker 运行日志、LLM 调用统计
  voices/<voiceId>/                   音色库（可迁移自现有 96 个内置音色）

    ref.wav                           参考音频
    sample.wav                        试听音频
```

### 4.2 实体

| 实体 | 关键字段 |
|---|---|
| `Book` | id、标题、来源文件、语言、章节数、状态、封面 |
| `Chapter` | index、标题、字符数、清洗后字符数、状态 |
| `Character` | id、主名、别名数组、性别、年龄段、性格底色、说话习惯、首次出现章、出现次数 |
| `Relationship` | from → to（有向）、亲疏/尊卑/敌意/亲密 四维（0–1）、说明、证据条数 |
| `Scene` | id、章、句区间、参与者、地点/时间提示、场景基调、摘要 |
| `Line` | id、场景、说话人、受话人（可空）、文本、情绪（主导+强度）、语气、停顿、语速、注音覆盖 |
| `Voice` | id、名称、参考音频、参考文本、标签、试听 |
| `Job` | 见 3.1 |

### 4.3 稳定 ID 规则

`c0007-s02-l014` = 第 7 章第 2 场景第 14 句。插入/删除只影响该 ID，不与位置绑定；音频文件名直接使用该 ID，因此**插入一句不会让后续句子全部重算**。

### 4.4 原子写规则

- 音频：写 `<lineId>.wav.tmp` → `fsync` → 原子改名；`.meta.json` 后写。元数据缺失一律视为未完成。
- JSON/JSONL：整文件"写临时文件 + 原子替换"；JSONL 按场景追加写，场景完成后落 `.done` 标记。
- 任何写操作前确保父目录存在；崩溃后不留半截文件。

## 5. 分析流水线

### 5.1 文本清洗（前置）

针对真实样本暴露的问题，《地球最后一个修仙者》原文含：

- 零宽字符行（`-‍﻿‍​‍‌‍﻿`）
- 站点广告行（`更多免费网盘资源，浏览器访问 mi.panlay.com`）
- 站点水印（`以下是啃书小说网`）
- 分隔线（`------------`、`卷一` 包裹行）
- 章节标题后缀（`第三章 洗髓伐脉（新书求收藏）`）

规则：去除零宽字符与不可见字符、按正则剔除广告/水印行、压缩重复分隔线、清洗标题后缀；**清洗统计写入 `chapters.json`，被丢弃的行原文留存备查**（避免误删正文后无法追查）。

### 5.2 三趟分析

> **变更（2026-09-28）**：取消 Pass B 场景切分与"场景切换停顿"。理由是场景层既不产生音色/情感收益，又让链路多一次 LLM 调用；
> 情感质量改由 Pass C 承担：整章按字符切窗口（`AB_LLM_LINE_WINDOW_CHARS`，默认 6000），每窗口注入"本段出现的角色 + 他们之间的关系四维"，
> 逐句给出说话人/受话人/主情绪+强度/**副情绪**（第二层情绪，如"笑着威胁"）/说话方式。行 id 仍是 `c{章}-s01-l{句}`（整章视为一段，保证音频缓存与历史 id 形态不变）。

| 趟次 | 频率 | 输入 | 输出 | 失败降级 |
|---|---|---|---|---|
| A 角色与关系 | 每章一次小调用 + 全局聚合一次 | 单章全文 | 本章角色、称呼、互动对象、关系证据 | 本章跳过并标记，不影响其他章 |
| C 逐句情感标注 | 每窗口一次（窗口不重叠） | 窗口文本 + 本段出现的角色底色 + 这些角色之间的关系四维 | 说话人、受话人、主情绪+强度、副情绪+权重、说话方式 | 该窗口全部按"旁白 + 沿用上一句情绪"，记入异常清单 |

关键约束：

1. **A 必须先于 C**，C 必须携带已知角色名单，否则模型会自由造名（"黑衣人""神秘人"），导致同一角色被拆成多个、音色分配错乱。
2. **别名合并**在 Pass A 的聚合阶段完成（苏锐/老苏/锐哥 = 同一人），否则同一角色会被分配多个音色。
3. **Pass C 只带相关上下文**：仅注入本窗口出现过的角色及其关系四维，控制 token 同时让"对谁说话"成为可用的情感判据。
4. **每趟都要求严格 JSON Schema 输出**，解析失败自动重试一次；仍失败才降级并记录。禁止使用"截取第一个 `[` 到最后一个 `]`"式的宽松解析。
5. 每次调用记录模型、token、耗时到 `logs/llm.jsonl`，用于成本核算与质量回溯。

### 5.3 四层优先级与参数推导

生效顺序：**句级 > 上一句（模型写"继承"时）> 关系 > 角色底色**。

模型只负责"这句话是什么情绪、怎么说的"；以下参数由规则推导，不交给模型逐句生成：

| 参数 | 推导规则（初版，可配置） |
|---|---|
| `pause_after_ms` | 句号 300 / 逗号 120 / 省略号 800 / 破折号 400；情绪强度 ≥0.8 追加 150（无场景切换停顿） |
| `rate` | 喊叫 ×1.05、耳语 ×0.92、冷笑 ×0.97 × 情绪系数（忧郁 0.92、悲伤 0.93、喜悦 1.04、愤怒 1.06…），限幅 0.85–1.15 |
| `lang` | 按字符集判定中/英/日等，中英混排取主语言 |
| `pronounce` | 仅对词典命中的专有名词/多音字注入（维护人名表），不让模型自由编造注音 |
| `emo_vector` | 由 `emotion.mix`（主情绪 + 副情绪及其权重）拼成引擎的 8 维向量；未标注的句子继承上一句→关系→角色底色 |

> **情绪通道（2026-09-28 追加）**：分析结果同时给两样东西 —— `emotion.mix`（8 维向量用）和 `emotion_text`（一句"怎么演"）。
> 产品默认把 `emotion_text` 发给 TTS 服务（服务端用 QwenEmotion 翻成向量），设置页可切回纯 8 维向量；
> 两条通道都必须能独立工作，缺 QwenEmotion 时自动退回向量。中文情绪名 → 引擎英文维度名的翻译在客户端做（`EMOTION_DIM_ALIASES`）。

### 5.4 自动选角（角色 → 音色）

现有音色库每个音色都带结构化标签：`name / gender / ageGroup / personality[] / genres[] / mood[] / speechRate / voiceQuality[] / languageStyle[] / usageType[] / description`（96 个音色，实测结构一致）。自动选角即"角色属性 × 音色标签"的打分：

1. **硬约束**：性别匹配，不匹配直接淘汰。
2. **高权重**：年龄段（青年/中年/老年）与角色一致；音色的 `speechRate` 与角色说话习惯一致。
3. **语义匹配**：角色性格底色、语气与音色的 `personality`、`mood`、`voiceQuality`、`description` 做相似度打分（规则词表 + 向量相似度；候选超过阈值时可由 LLM 在 Top5 内选定并给出理由）。
4. **先验**：`genres`（都市/古风/言情…）与 `usageType`（角色对话/旁白）作为加权项。
5. **冲突处理**：同一音色被多个主要角色命中时，按角色出现次数与戏份排序分配，其余角色退到次优音色；**旁白固定占用专用音色，不参与角色竞争**（否则旁白和主角会撞音色）。

输出写入 `voices/casting.json`（角色 id → 音色 id + 覆盖参数）。UI 允许人工调整，但它不是流程关卡。

## 6. 合成、缓存与断点

### 6.1 缓存键

```
key = sha256( text
            + voiceId
            + engineName + engineVersion
            + 实际生效的参数（emoVector / rate / pronounce / lang / format） )
```

- 键与生成时间、token 统计、音频时长一起写入 `<lineId>.meta.json`。
- **只把引擎声明支持的参数计入哈希**：适配层上报能力集（如某引擎不支持注音），不支持的参数不参与，避免换引擎导致整本缓存失效、白跑数小时。
- 重算判定：键一致 → 跳过；否则重生成该行，其余行不动。

### 6.2 合成流程

1. worker 领取章级 `synthesize` 任务，章内**按行并行**投递给 TTS 服务。
2. 参考音频不逐句上传：首次上传得到 `refId`，之后只传 `refId`（服务端缓存参考音频及其预处理结果，这是最直接的提速点）。
3. 每行：写 `.tmp` → 原子改名 → 写 `.meta.json` → 更新进度。
4. 失败按 3.4 分类处理，跳过并记录，不阻塞全章。

## 7. 引擎适配层与 TTS 服务

### 7.1 后端侧适配层

```python
class EngineAdapter(Protocol):
    def capabilities(self) -> EngineCapabilities: ...
    def synthesize(self, line: Line, voice: Voice, params: SynthParams) -> AudioResult: ...
```

上层（调度、缓存、UI）只依赖"能力集 + 合成接口"，不认识任何具体引擎。以后接入 OmniVoice / GPT-SoVITS / CosyVoice，只需新增一个 adapter 与服务端封装。

### 7.2 TTS 服务 HTTP 契约

| 接口 | 说明 |
|---|---|
| `GET /health` | `status`、`modelLoaded`、`device`、`vramTotalMB`、`vramUsedMB`、`recommendedConcurrency`、`inflight`、`avgInferenceSecPerAudioSec`、`engine`、`modelSource` |
| `GET /capabilities` | 是否支持情绪（维度名）、语速、注音（拼音/CMU/假名）、语言列表、采样率、单次文本上限 |
| `POST /v1/refs` | 上传参考音频一次，返回 `refId` |
| `POST /v1/synthesize` | 入参 `text / refId / lang / emoVector / rate / pronunciation / format / seed`；回传音频流 + 时长 + 引擎版本 + 耗时 |
| `POST /warmup`、`POST /unload` | 预加载 / 释放显存，便于与其他 GPU 任务共存 |

能力集驱动的三个后果：后端只发送引擎支持的参数；UI 据此显示或隐藏控件；缓存键只包含实际生效参数。

### 7.3 模型来源三选一

配置项 `model.source = modelscope | huggingface | local`：

- `modelscope`：适合国内网络直连下载
- `huggingface`：支持 `HF_ENDPOINT` 镜像
- `local`：直接指定本地 IndexTTS-2.5 路径，跳过下载，可完全离线

三种来源最终落到统一目录布局。配套要求：

1. **权重校验**：维护 `manifest.json`（文件名 + 大小 + sha256），启动时校验，不匹配直接报错并提示换源/重下。
2. **辅助模型同源同校验**：w2v-bert-2.0、MaskGCT 语义编解码器、CAMPPlus、BigVGAN 不属于主仓库，IndexTTS 首次推理才拉取 —— 必须纳入同一套来源与校验逻辑，支持预置缓存，否则内网/离线机器会卡在首次推理。
3. **断点续传**：已存在且校验通过的文件跳过下载。

### 7.4 多实例与生命周期

- 后端配置 `tts.endpoints[]`，可指向不同端口或不同机器，按权重分发；每个实例自报可用并发，worker 汇总为总投递上限。
- TTS 独立启动/重启；`serve` 启动时探测，未就绪时明确提示"请先启动 TTS 服务"，不静默失败。
- 每行 `.meta.json` 记录引擎名与版本，作为缓存键的一部分。

## 8. 产物与导出

| 产物 | 说明 |
|---|---|
| `chapter_N.wav` / `.srt` | 章节音频与字幕，**字幕时间轴由真实音频时长（含插入的停顿）累计**，不再按字符数估算 |
| `chapter_N.mkv` | 音频 + 内嵌软字幕，可选章节标记 |
| `book.wav` / `.srt` / `.mkv` | 整本合本，带章节标记与统一的时间轴 |

采样率策略：同书内若存在不同采样率（例如混用不同引擎），合并时必须**显式重采样到统一采样率**。实测证据：24kHz 与 22.05kHz 片段各 1 秒直接拼接，输出 1.9187 秒且第二段变速变调，ffmpeg 不报错 —— 这类静默损坏必须在流水线里被检测并阻断。

响度：章节与整本导出统一做响度归一，默认目标 **-16 LUFS（单声道）、真峰值 ≤ -1.5 dBTP**（设置中可调；如需对齐有声书平台标准可切到 -18 ~ -23 dB RMS 档位），避免不同音色、不同引擎之间忽大忽小。

## 9. UI 设计

### 9.1 结构

主线三层：**书架 → 书 → 章 → 场景 → 句子**

- 书架：卡片显示封面、"第 38/155 章 · 已生成 6h12m"、状态（分析中/合成中/异常 N 处）、一键继续
- 书：章节列表带状态列，整本导出入口、任务中心入口
- 章：场景卡片（参与者、基调、摘要、时长）→ 句子列表（说话人、受话人、情绪标签、试听、单句重生成）
- 句子：试听、改文本/角色/情绪/停顿，**只重生成这一句**

辅助页：任务中心（运行中/排队/失败 + 暂停/取消/ETA）、音色库（试听、标签筛选、上传参考音频、角色→音色矩阵）、异常清单（降级与失败，可批量重试）、设置（LLM 与 TTS 端点、模型来源、输出与响度、导出）。

### 9.2 交互原则

1. 默认路径只有三个动作：**导入、一键分析、一键生成**，中途无强制确认。
2. 所有人工操作都是事后修正，不是流程关卡。
3. 关闭浏览器不影响后台任务；手机连上来可看进度、可试听。

### 9.3 视觉方向（按 `frontend-design` 技能执行）

实施 M4 时必须加载 `frontend-design` 技能，并遵守其要求：

- **确定一个明确的审美方向**：本项目取"编辑台 / 活字印刷"方向（书稿、排字、校对的隐喻），深色为默认主题（长会话），纸白与墨黑为主色，单一强调色（朱砂红或琥珀金）少量使用。
- **字体**：标题用有性格的中文衬线（如思源宋体/Noto Serif SC），数据与进度用等宽字体（如 JetBrains Mono / IBM Plex Mono），正文用思源黑体；**禁止以 Inter / Roboto / Arial / 系统默认字体作为主要视觉方案**。
- **禁止**：紫蓝渐变、玻璃拟态卡片、超大圆角卡片墙、千篇一律的 SaaS 布局、装饰性色块。
- **必须**：空态/加载态/错误态完备；键盘可达与可见焦点；hover/active/disabled 状态；移动端与桌面端断点；颜色/间距/阴影/字阶用 CSS 变量。
- 交付前按技能的自检清单逐条核对（移动端可用、文字不溢出、状态完备、无 AI 生成式套路、有一个能被记住的记忆点）。

## 12. 测试策略

1. **假引擎（Fake Engine）**：输出可控波形、可注入失败与延迟，使整条流水线能在无 GPU、无模型的机器上端到端跑通 —— M0 的验收依赖它。
2. **契约测试**：每个 adapter 跑同一组用例，保证"声明的能力集"与"实际行为"一致。
3. **队列测试**：并发领取不重复、租约过期回收、重试退避、毒丸跳过。
4. **缓存测试**：改文本/参数后只有目标行重算；换引擎时缓存按能力集正确失效。
5. **产物测试**：混采样率合并被正确重采样；字幕时间轴与音频时长一致。
6. **迁移测试**：96 个音色全部可试听；样本书从导入到出成品可跑通。
7. **UI 冒烟**：三层导航、试听、单句重生成、移动端断点。

## 14. 已知风险与缓解

| 风险 | 缓解 |
|---|---|
| IndexTTS-2.5 在部署机器上显存/速度不达预期 | 服务端自报 `recommendedConcurrency`，worker 自适应；必要时 `unload` 释放；部署机器可更换（用户有其他机器） |
| 模型下载被网络阻断 | 三种来源 + 镜像配置 + 权重校验 + 离线 `local` 模式 |
| LLM 输出不稳定 | 严格 Schema + 重试一次 + 降级可见（写异常清单） |
| 长文本分析成本不可控 | 分场景调用、只注入相关上下文；逐次记录 token 与耗时 |
| 文本清洗误删正文 | 只删除命中规则的行，原文留存并在报告中给出统计 |
| 人工零介入下质量问题被掩盖 | 异常清单 + 章节级质检（空音频、时长异常、情绪与关系冲突）汇总为"体检报告" |
